# Отчёт по этапу MVP

## 1. Контекст этапа

Предыдущий этап проекта оформлен в файле `report.md` и соответствует стадии прототипа.

Текущий документ фиксирует, что было сделано на этапе MVP, какие требования были закрыты, какие решения появились сверх исходного плана и что остаётся перенести в следующий этап.

## 2. Что требовалось на MVP

По исходному плану на этапе MVP должны были появиться:

- ручное добавление камер
- автообнаружение камер
- полное PTZ-управление
- работа с пресетами
- отображение видео
- кроссплатформенность
- документация пользователя и разработчика
- отзыв пользователя

## 3. Что сделано в этом этапе

### 3.1 Базовые требования MVP

| Пункт | Статус | Комментарий |
|---|---|---|
| Ручное добавление камер | ✅ | Реализовано через Add Camera и локальное сохранение конфигурации |
| Полное PTZ-управление | ✅ | Continuous, Relative, Absolute, hotkeys, stop |
| Работа с пресетами | ✅ | Просмотр, поиск, вызов, создание, удаление |
| Отображение видео | ✅ | RTSP через PyAV |
| Кроссплатформенность | ✅ | Исходники кроссплатформенные; Windows, Linux, macOS standalone проверен|
| Документация пользователя и разработчика | ✅ | Добавлены отдельные markdown-документы |

### 3.2 Что появилось сверх исходного MVP

Фактический объём разработки вышел дальше минимального MVP. Дополнительно реализованы:

- одновременная работа с несколькими камерами
- browser-style вкладки камер
- локальная библиотека сохранённых камер
- Matrix mode
- переключение и редактирование media profiles
- редактор video streaming settings
- динамический editor imaging settings
- поддержка камер без PTZ
- административные разделы ONVIF Device Management:
  - Network Settings
  - Maintenance
  - User Management
- standalone build для всех платформ

## 4. Изменения по архитектуре относительно прототипа

### 4.1 UI

Приложение ушло от простой схемы «одно окно, одна камера» к более зрелой структуре:

- левая activity rail для добавления и списка камер
- центральное рабочее пространство с вкладками и Matrix
- правая inspector rail с разделами по функциям камеры

### 4.2 Модель данных

Появилась полноценная модель сессии камеры:

- ONVIF client
- loop
- active profile
- RTSP URI
- состояние вкладки
- состояние Matrix tile

### 4.3 ONVIF-слой

Интеграция расширилась с базового PTZ/media-набора до Device Management:

- network interfaces
- hostname / DNS / NTP
- discovery / zero configuration
- users
- reboot / factory reset / firmware upgrade

## 5. Технический результат этапа

### 5.1 Реализованный функциональный результат

На момент завершения этапа доступны следующие пользовательские сценарии:

1. Добавить несколько камер вручную и сохранить их локально.
2. Открывать камеры по клику из Saved Cameras.
3. Смотреть одиночный поток или переносить камеры в Matrix mode.
4. Управлять PTZ мышью и клавиатурой.
5. Работать с пресетами.
6. Менять параметры encoder и imaging settings.
7. Управлять media profiles.
8. Просматривать и частично менять сетевые настройки камеры.
9. Выполнять maintenance-операции и управлять пользователями камеры.
10. Собрать standalone-приложение для Windows/Linux/macOS.

### 5.2 Результат по качеству реализации

Дополнительно были решены практические проблемы, типичные для реальной эксплуатации:

- поддержка камер без PTZ без падения интерфейса
- корректная обработка optional ONVIF services

## 6. Артефакты этапа

По итогам этапа в проекте есть:

- исходный код приложения
- standalone build pipeline
- release-сборка для Windows/Linux/macOS
- документация разработчика
- документация пользователя
- обновлённый отчёт по этапу MVP


## 7. Вывод по этапу

По программной части проект достиг рабочего состояния уровня MVP и частично зашёл дальше него. Базовые пользовательские сценарии управления ONVIF-камерами закрыты, интерфейс стал пригоден для постоянного использования, а сборка для Windows/Linux/macOS доведена до standalone-формата.

Все ключевые элементы MVP реализованы, а часть функций уже относится к следующему уровню зрелости продукта.
